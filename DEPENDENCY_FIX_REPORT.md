# Angular Dependency Conflict Fix Report

## Objective
Fix the Vercel deployment failure caused by Angular dependency version conflict between `@angular/common`, `@angular/animations`, and `ngx-bootstrap`.

## Problem
Vercel reported ERESOLVE dependency conflict:
- `@angular/animations` was resolved to `20.1.8` (incompatible)
- `ngx-bootstrap@20.0.1` requires `@angular/animations ^20.0.2`
- Project's `@angular/common` and `@angular/core` were at `^20.2.0`

The root cause: `@angular/animations` was not declared as an explicit dependency in `package.json`, so npm resolved it to a different version than what `ngx-bootstrap` expected.

## Solution
Added `@angular/animations` as an explicit dependency at version `^20.2.0` to align with the other Angular packages.

## Changes Made

### 1. client/package.json
- Added `"@angular/animations": "^20.2.0"` dependency

### 2. client/package-lock.json
- Regenerated by `npm install` / `npm ci` to resolve all peer dependencies correctly

### 3. .gitignore
- Removed `package-lock.json` from ignore list so the lock file is tracked in Git

## Resolved Dependency Versions
All Angular packages now resolve to compatible versions:
- `@angular/animations`: 20.2.3

- `@angular/core`: 20.2.3
- `@angular/cdk`: 20.2.1
- `@angular/material`: 20.2.1
